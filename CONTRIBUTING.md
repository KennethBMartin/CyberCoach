# Contributing to Project CyberCoach

Thank you for your interest in helping scale Project CyberCoach! This project is an entirely community-driven, public-good endeavor. The original founders do not manage this repository day-to-day. It operates on an automated, peer-reviewed governance structure. 

By contributing, you help make continuous, zero-willpower metabolic health and behavioral modification accessible to everyone for free.

---

## 🏗️ Core Architecture Priorities

We welcome contributions across our three modular layers, with a heavy emphasis on zero-cloud privacy and balanced psychological conditioning:

1. **The Behavioral Ledger (Data Ingestion):** Expanding local API bridges using the Open Wearables core to read incoming smart ring, fitness band, and biometric data entirely on-device.
2. **The Dynamic Feedback Loop (The Carrot & The Stick):** 
   * **The Stick:** Refining the real-time audio nudge thresholds (Levels 1–5) and smart-home physical friction scripts (e.g., Zigbee cabinet locks or tracking gesture telemetry to intercept micro-habits like cheek chewing and smoking).
   * **The Carrot (The Dopamine Reward Engine):** Developing algorithms that calculate the precise, optimal physiological moments to deliver positive reinforcement. The AI should push high-praise metrics ("Metabolic alignment achieved," "Habit disruption milestone verified") to trigger healthy dopamine rewards that balance out necessary corrections.
3. **Local Edge AI Inference:** Optimizing low-latency execution of open-source models (like Llama-3 or Phi-3) using ONNX or vLLM to run smoothly on standard smartphone NPUs without draining battery.

---

## 🚀 How to Contribute Code

To keep this project running seamlessly without centralized management, we follow a strict automated pipeline:

1. **Fork the Repository:** Create your own branch from the `main` branch.
2. **Implement Security Best Practices:** Ensure no data strings leave the local device environment. All sensitive variables must be handled via local encryption utilizing our SHA-256 key-derivation protocol.
3. **Submit a Pull Request (PR):** Link your PR to an open issue.
4. **Automated Testing & Peer Review:** GitHub Actions will automatically scan your code for security vulnerabilities. Two appointed Community Maintainers must review and approve the PR before it is merged.
